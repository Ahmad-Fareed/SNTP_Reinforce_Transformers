# SE4095 Assignment 03 - Sequential Influence Maximization

This project implements the complete Assignment 03 pipeline for **SE4095 Social
Network Theory and Practice**. A reinforcement-learning agent selects five
participants sequentially from a fixed 92-person workplace contact network. The
policy is trained with REINFORCE, in two required architectures: an MLP and a
Transformer. The learned policies are compared with Random and Degree selection
under identical Independent Cascade realisations.

The submission includes the trained checkpoints, all required CSV files, the
figures, the automated check results, and a searchable PDF report.

## Dataset

The input is the instructor-supplied static package derived from the
SocioPatterns **Contacts in a Workplace** release (collected 24 June to 3 July
2013):

| File | Content |
|---|---|
| `data/nodes.csv` | 92 participants: `node_id,original_id` |
| `data/edges.csv` | 755 unique undirected contacts: `source,target` |
| `data/departments.csv` | 92 department labels: `node_id,department` |
| `data/dataset_README.md` | supplied package notes and SHA-256 hashes |

The graph is undirected and unweighted. It has 92 participants, 755 edges,
density `2E/[N(N-1)] = 0.180363`, one connected component, no isolates, and five
recorded department labels. The CSV files are loaded unchanged; `main.py`
verifies their published SHA-256 hashes before use. Department labels are
descriptive only and never enter a policy, reward, or tuning decision.

Attribution: SocioPatterns, *Contacts in a Workplace*; Génois et al.,
"Data on face-to-face contacts in an office building suggest a low-cost
vaccination strategy based on community linkers", *Network Science* 3,
326-347, 2015. Dataset page:
<https://sociopatterns.org/datasets/contacts-in-a-workplace/>.

## Running the assignment

From the project root:

```bash
python main.py --output results
```

The command is relative-path based and does not depend on the machine's
absolute directory. It performs the following steps:

1. Validates the supplied data hashes and builds the fixed graph.
2. Computes the network statistics and writes `results/graph_edges.csv`.
3. Trains both architectures with seeds 7, 21, and 42 (six runs, 1,000
   episodes each, 50 REINFORCE updates per run).
4. Saves the six final checkpoints and `training.csv` (6,000 rows).
5. Evaluates Random, Degree, and all six checkpoints on diffusion seeds
   900000-900099 (`evaluation.csv`, 800 rows).
6. Writes `summary.csv` (8 rows), architecture/selection/coverage tables,
   figures, and `checks.json`.
7. Builds the searchable `report.pdf`.

All random seeds and diffusion-seed formulas are fixed by the assignment.
Actual training and evaluation use Independent Cascade probability `0.10`;
probabilities 0 and 1 appear only in verification checks.

## Generated outputs and timing

The required files are written to `results/`. The report is written to the
project root as `report.pdf`. Timings are measured with `time.perf_counter`:

- **Training time** includes all training simulations and the optimizer work.
- **Selection time** in `evaluation.csv` excludes diffusion and environment
  updates. For neural policies it measures the observation-to-logit computation,
  action masking, and greedy argmax at each of the five selections; for Random
  it includes the separate generator's sampling.

## Hardware and measured runtime

The reported run used:

- Windows 11 (10.0.26300), Python 3.12.10
- Intel Core i7-7820HQ CPU @ 2.90 GHz, 4 cores / 8 logical processors
- 16 GB RAM
- CPU-only PyTorch 2.15.0+cpu

On this machine the complete pipeline (six training runs, 800 evaluation
episodes, figures, checks, and report generation) takes roughly **1.7-1.8
minutes** (101.1 s in the reported run). Training alone averages about **8.4 s
per MLP run** and **21.8 s per Transformer run**; greedy selection averages
about **2.1 ms per MLP episode** and **4.3 ms per Transformer episode**. These
numbers are machine-specific and are also recorded in
`results/run_metadata.json` and the report.

page in the included report).

## Interpretation and limitations

The graph is a static aggregation: contact timing and duration are discarded.
Independent Cascade at 0.10 is a simulation assumption, not observed message
adoption. The study uses one 92-person graph, three training seeds, and 100
shared evaluation realisations. No hyperparameter search or evaluation-based
tuning was performed. Department coverage is descriptive only. A learned policy
is not required to outperform Degree, and no claim beyond this fixed graph and
simulator is made.
